# Ticket monitor

Собирает билеты с tixxa.co и tixbay.com в Google Таблицу (листы «Актуальные», «История», «Лог»).

## Настройка
1. Google Cloud: создать проект, включить **Google Sheets API**, создать **Service Account**, скачать ключ (JSON).
2. Создать Google Таблицу и дать доступ (редактор) на e-mail сервисного аккаунта.
3. В GitHub: Settings -> Secrets and variables -> Actions:
   - `GOOGLE_CREDENTIALS_JSON` - весь текст JSON-ключа;
   - `SPREADSHEET_ID` - часть ссылки на таблицу между `/d/` и `/edit`.
   - `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` - бот и id группы для уведомлений о падении пайплайна (необязательно).
4. Залить проект в репозиторий, на вкладке Actions запустить «Ticket monitor» кнопкой Run workflow.

## Добавление концертов
Файл `src/main/resources/events.csv`: новая строка `yes;tixxa|tixbay;Название;Город;Страна;Дата;URL`.

## Tixbay
Названия полей JSON берутся из `src/main/resources/tixbay-mapping.properties`.
Если данных с tixbay нет или они странные, откройте запуск в Actions, скачайте артефакт `debug`
и поправьте названия полей в этом файле.

## Таблица для клиентов
Отдельный Google-документ (не лист основной таблицы): основная таблица - для менеджера, эта - для клиента.
1. Дайте сервисному аккаунту доступ «Редактор» к клиентскому документу.
2. В GitHub Secrets добавьте `CLIENTS_SPREADSHEET_ID` (часть ссылки между `/d/` и `/edit`).
   Без него клиентская таблица пропускается (предупреждение в логе).
3. Запись идёт в первый лист документа; он автоматически называется «Главная».
4. Рекомендуемые названия документов: «Предложения для менеджера» и «Предложения для клиента» (меняются вручную в Google).
   В основном документе данные пишутся на лист «Предложения для менеджера»; если его нет, он создаётся автоматически.

Колонки: Название концерта, Страна, Дата, Сектор, Количество, Итоговая стоимость за 1 шт. (₽).
Сумма = количество × (цена × курс ЦБ + комиссия 32 000 ₽ за билет). Если курса нет - ячейка пустая.
Таблица полностью перезаписывается при каждом запуске.

## Колонки «мест подряд»
«Макс. мест подряд» - самая длинная цепочка свободных соседних мест в ряду.
«Блоков подряд» - сколько цепочек длиной 1 / 2 / 3 / 4+. Фильтр «нужно 3 места рядом» -
это фильтр по колонке «Макс. мест подряд» >= 3.

## Проверки перед запуском (обновление октябрь 2026)
`mvn clean verify` — проверка защитной логики и загрузчика событий (нужен Python 3 и JDK 17).
`mvn test` — компиляция Maven-проекта; обе команды запускаются в GitHub Actions до сбора билетов.
Ошибки парсинга и неполная пагинация Tixxa теперь помечают событие как `НЕ ПРОВЕРЕНО`; такие данные не заменяют успешно проверенные старые строки.
Подробности и ограничения: `TEST_REPORT.md`.


## Автоматические тесты

`mvn clean verify` запускает JUnit 5 тесты. Подробности — в [JUNIT_TESTS.md](JUNIT_TESTS.md).

## Итоговая стоимость
Колонка «Итоговая стоимость за 1 шт. (₽)» = цена за 1 шт. × курс ЦБ РФ (cbr-xml-daily.ru, на момент запуска) + 32 000 ₽ комиссии, затем округление вверх до ближайшей 1 000 ₽. Расчёт одинаков для таблиц клиента и менеджера и не зависит от количества билетов в лоте.
На количество и разницу с курсом банка (~2 000 ₽) умножаем/добавляем вручную. Сумма комиссии - в `Cost.java`.
Если курс валюты не получен - ячейка пустая. Колонка «Статус» удалена; данные теперь в A:P.
